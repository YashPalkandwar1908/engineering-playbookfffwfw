# Project Types

Different projects need different structures. There is no single folder structure that fits everything.

Use the project type as a starting point, then adapt the structure to the project's actual needs.

## Common Project Types

```text
Software Projects
│
├── Web Applications
│   ├── Full-stack
│   ├── Frontend
│   └── Backend / API
│
├── Applications
│   ├── Mobile
│   └── Desktop
│
├── Developer Tools
│   ├── CLI
│   ├── Library
│   ├── SDK
│   ├── Plugin
│   └── Automation
│
├── AI / Data
│   ├── AI
│   ├── Machine Learning
│   ├── Data / Analytics
│   └── Computer Vision
│
└── Research
    ├── Experiments
    ├── Prototypes
    └── Research Projects
```

## Typical Structures

| Project Type    | Typical Areas                                        |
| --------------- | ---------------------------------------------------- |
| Full-stack      | `frontend/`, `backend/`                              |
| Frontend        | `components/`, `pages/`, `services/`                 |
| Backend / API   | `handlers/`, `services/`, `repositories/`, `models/` |
| Mobile          | `screens/`, `components/`, `services/`               |
| Desktop         | `ui/`, `services/`, `models/`                        |
| CLI             | `commands/`, `services/`, `utils/`                   |
| Library / SDK   | `core/`, `models/`, `clients/`                       |
| AI / ML         | `data/`, `models/`, `training/`, `inference/`        |
| Data            | `ingestion/`, `processing/`, `pipelines/`            |
| Computer Vision | `detection/`, `tracking/`, `inference/`              |
| Research        | `experiments/`, `notebooks/`, `results/`             |

## Important

These are **starting points, not rules**.

A project can combine multiple types or use a completely different structure when its requirements justify it.

> **Choose structure based on what the project does, not on a template.**

This document can be expanded later as new project types or patterns become relevant.
